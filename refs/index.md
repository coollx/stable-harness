| HCL | *Harness Continual Learning: Continual Adaptation Beyond Model Parameters* ([paper.pdf](related-work/HCL/paper.pdf)) | method | ❌ no public code | Defines Harness Continual Learning (HCL): a frozen foundation model with a mutable harness (task interface, experience memory, inner skills, router) updated by an untrained proposer behind a commit gate requiring current-task improvement, bounded anchor damage, and validity. Evaluated on ALFWorld, Minecraft, textual and multimodal streams; the tolerance sweep shows forgetting rising monotonically while final performance peaks at an intermediate setting. Plasticity is named but never defined or measured; weights, tools, and the update machinery itself are never modified — our named falsifier baseline. [arXiv:2608.19013](https://arxiv.org/abs/2608.19013) | [paper_analysis.md](related-work/HCL/paper_analysis.md) |
| Agent-Harness-Survey | *Agent Harness Engineering: A Survey* ([paper.pdf](related-work/Agent-Harness-Survey/paper.pdf)) | empirical | ✅ [repo/](related-work/Agent-Harness-Survey/repo) · [src](https://github.com/Picrew/awesome-agent-harness) (catalog, not an implementation) | 71-page survey plus systematic mapping study: defines the harness as an engineering layer distinct from the model, proposes the seven-layer ETCLOVG taxonomy (execution, tooling, context, lifecycle, observability, verification, governance), and codes 171 catalogued open-source artifacts onto it; lifecycle, verification, and execution are dense, observability and governance thin, context tooling embedded. Names harness self-optimisation (Meta-Harness, observability-driven evolution, benchmark-gated loops) an open direction and warns that narrow-suite self-optimisation breeds brittleness; every instance it lists scores the current batch. The repo is the living catalog (367 entries, 9 categories, YAML plus render and verify scripts), a scan list for related self-improving harnesses and inspectable open harnesses. [OpenReview eONq7FdiHa](https://openreview.net/forum?id=eONq7FdiHa) · [project page](https://picrew.github.io/LLM-Harness/) | [paper_analysis.md](related-work/Agent-Harness-Survey/paper_analysis.md) · [repo_analysis.md](related-work/Agent-Harness-Survey/repo_analysis.md) |
| Harness-Anatomy | *Harness Engineering: Anatomy, Architecture, and Evolution of Coding Agents — A Source-Code Study of Eleven Systems* ([paper.pdf](related-work/Harness-Anatomy/paper.pdf)) | empirical | ❌ no public code | Source-code audit of eleven production coding harnesses (Claude Code, Codex, Gemini CLI, Mistral Vibe, OpenHands, Aider, Mini-SWE-Agent, Hermes, Pi, OpenCode, OpenClaw) plus the Omnigent meta-harness, pinned to July 2026 with April snapshots diffed for eight of them; yields a seven-subsystem anatomy, 13 observations, 29 patterns, and 18 recommendations. Headline absences: no agentic framework and no embedding retrieval over code in any runtime; skills (9/11) lead MCP (8/11); convergence became imitation within one quarter. For us: the layer list is grounded in production, the three in-the-wild self-improving write paths (Codex agent-maintained memory, Hermes skill loop, Gemini CLI human-gated inbox) all score on current use and never on later tasks, and the pinned public git histories are human harness-evolution logs. [arXiv:2609.00006](https://arxiv.org/abs/2609.00006) | [paper_analysis.md](related-work/Harness-Anatomy/paper_analysis.md) |
